# Tabs Design Spec

- Component: Tabs
- Category: Components

- Figma:

- Runtime scope: horizontal tabs with per-tab panel, optional close, optional add-tab, responsive overflow with More menu

## Anatomy
- **root**: top-level tabs container.
- **listWrap**: horizontal clipping container for the tab row.
- **tablist**: interactive list (`role="tablist"`), contains visible tabs and optional More trigger.
- **tab**: one tab button (`role="tab"`), optional leading icon, text label, optional close action.
- **tabLabel**: text node inside tab button, truncates with ellipsis.
- **tabClose** (optional): close control per tab.
- **addTabTrigger** (optional): add new tab action at tab-row end.
- **moreTrigger** (conditional): overflow trigger labeled "More" with down chevron icon.
- **moreMenu** (conditional): menu listing hidden tabs.
- **panelRegion**: container for tab panels.
- **tabPanel**: content region for the active tab (`role="tabpanel"`).

## Layout & Measurements
- Root uses container-driven width: `width: 100%`, `box-sizing: border-box`.
- Tab row is horizontal and non-wrapping: `display: flex`, `align-items: stretch`, `white-space: nowrap`.
- Tab row bottom baseline: single `1px` line using `var(--color-border-light)`.
- Vertical separators between tabs: `1px` using `var(--color-border-light)`.
- Tab control height: `32px`.
- Tab item padding: `6px 8px 6px 16px` (top/right/bottom/left).
- Each tab width constraints:
  - **minimum**: `80px`
  - **maximum**: `250px`
  - min/max include label + optional tab icon + optional close icon.
- Tab label overflow rule:
  - label area is flexible (`flex: 1 1 auto`, `min-width: 0`)
  - apply `overflow: hidden; text-overflow: ellipsis; white-space: nowrap`.
- Close icon target is right-aligned within tab and included in width budget.
- More trigger remains visible at row end when hidden tabs exist.
- More trigger label/icon spacing: `var(--component-gap-s, var(--spacing-space-8))` (`8px` effective).
- Overflow behavior is responsive to container width changes (observe root/list width; recompute visible tabs on resize).
- Active panel is rendered below tab row with full available width.

## Interactions
- **Tab activation**:
  - Clicking a tab activates it and displays its panel.
  - Exactly one tab is active at a time.
- **Closable tabs**:
  - Each tab may show a close action when `closable=true` for that tab.
  - Closing the active tab activates the nearest surviving tab (prefer right sibling, else left).
  - Closing must be blocked when only one tab remains (one tab must always exist).
- **Add tab (optional)**:
  - Add action uses icon slug `shape-plus` (`assets/icons/shape-plus.svg`).
  - Trigger can appear at tab-row end when enabled.
- **Overflow / More**:
  - If tabs exceed available container width, move trailing non-active tabs into hidden collection.
  - Show `More` trigger with chevron-down icon (`chev-down.svg`, 12px).
  - Clicking More opens a list of hidden tabs.
  - When user selects a hidden tab from More list:
    1. selected hidden tab becomes active,
    2. selected tab is promoted into visible row,
    3. one currently visible tab is demoted to hidden so visible slot count stays stable,
    4. More remains as overflow entry point if hidden tabs still exist.
- **Optional tab icon with label**:
  - Tab may include an icon before label when provided.
  - Icon is decorative unless product defines semantic meaning.
- **Keyboard**:
  - `ArrowLeft`/`ArrowRight`: move focus across visible tabs.
  - `Home`/`End`: jump focus to first/last visible tab.
  - `Enter`/`Space`: activate focused tab.
  - `Delete` (optional): close focused tab if closable and more than one tab exists.
  - `Enter`/`Space` on More opens hidden-tab menu; arrows navigate menu; Enter selects.

## Composition & API (runtime)
| Slot/Prop | Required | Behavior |
|---|---|---|
| `tabs` | Yes | Ordered list of tab models. Each item: `{ id, label, panel, icon?, closable?, disabled? }`. |
| `activeTabId` | Yes (controlled) | Currently active tab id. |
| `defaultActiveTabId` | No (uncontrolled) | Initial active tab id when uncontrolled mode is used. |
| `onActiveTabChange(id)` | Yes | Fired when active tab changes via click/keyboard/overflow selection. |
| `onTabClose(id)` | No | Fired when a tab close action succeeds. Must not fire when close is blocked by single-tab rule. |
| `allowAddTab` | No | Enables Add tab trigger. |
| `onAddTab()` | No | Called when add trigger is clicked/activated. |
| `showMoreOverflow` | No (default `true`) | Enables responsive overflow-to-More behavior. |
| `moreLabel` | No (default `"More"`) | Localizable label for overflow trigger. |
| `minTabWidth` | No (default `80`) | Minimum width in px for a tab item. |
| `maxTabWidth` | No (default `250`) | Maximum width in px for a tab item. |
| `renderTabIcon` / `icon` field | No | Optional icon renderer/value for icon+label tabs. |

Implementation rules:
- Always keep at least one tab item in runtime state.
- Enforce `minTabWidth` and `maxTabWidth` at render/layout level.
- Tab label truncation must be deterministic and token-compatible.
- Panels are associated by stable id mapping (`tab.id` ↔ `tabpanel` id).

## Codegen Contract (Framework-Agnostic Blueprint)
### Deterministic slot schema
- `root`
  - `listWrap`
    - `tablist`
      - `visibleTab[]`
      - optional `moreTrigger`
      - optional `addTabTrigger`
    - optional `moreMenu`
  - `panelRegion`
    - `activeTabPanel`

### Supported matrix
- Tab visibility mode: all-visible | overflow-with-more.
- Tab composition: label-only | icon+label.
- Close mode: non-closable | mixed closable | all closable (still one-tab minimum).
- Add mode: no add trigger | add trigger enabled.
- Control mode: controlled | uncontrolled.

### Style contract
- Tab item width clamp: `min 80px`, `max 250px`.
- Tab item height: `32px`.
- Tab padding: `6px 8px 6px 16px`.
- Truncation is required for labels exceeding available width.
- More chevron icon is **12px**.
- All style values use semantic tokens except fixed width constraints above.
- Responsive overflow recalculates on:
  - container resize,
  - tab add/remove,
  - label/icon changes that affect measured width.

### Behavior contract
- Selection from More promotes selected hidden tab into visible active set.
- Active tab must always have a panel rendered.
- Close action cannot remove final remaining tab.
- Closing a tab preserves deterministic next-active selection logic.

### Accessibility contract
- `tablist` has `role="tablist"`.
- Each tab has `role="tab"`, `aria-selected`, `aria-controls`, and stable `id`.
- Each panel has `role="tabpanel"` and `aria-labelledby`.
- More trigger has button semantics + expanded state when menu is open.
- Hidden-tab list uses menu/listbox semantics consistently per framework primitive.

### Asset and bundling contract
- Required assets:
  - Add tab icon: `assets/icons/shape-plus.svg` (user wording "shape-plush" maps to `shape-plus` asset slug).
  - More chevron: `assets/icons/chev-down.svg` (12px render size).
- Asset folder must be available in framework bundle/runtime path when generating code.

### Fallback/error rules
- Missing `activeTabId`: fallback to first available tab.
- Invalid `activeTabId`: fallback to first non-disabled tab.
- Empty tabs input: generator/runtime must create one default non-closable tab placeholder.
- Unknown icon slug: render label without icon; do not crash.

### Validation checklist
- [ ] One-tab-minimum invariant is enforced.
- [ ] Min/max tab width constraints are enforced (80/250).
- [ ] Long labels truncate with ellipsis.
- [ ] Overflow switches to More when tabs exceed container width.
- [ ] Selecting hidden tab from More promotes it to visible active tab.
- [ ] More chevron icon renders at 12px.
- [ ] Optional add-tab icon uses `shape-plus` asset.
- [ ] Keyboard + ARIA behavior conforms to tab pattern and overflow menu behavior.
- [ ] Light/dark states are token-driven only.
