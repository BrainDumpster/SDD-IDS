## Anatomy

- **viewport**: fixed stack container for toast items.
- **toast root**: single-row notification shell.
- **content**: message text block.
- **alerting icon**: left icon indicating alert type.
- **link action (optional)**: inline "View Details" action.
- **close action (optional/closable)**: trailing dismiss icon button.

## Alerting icons (canonical assets)

Toast alerting types must use these **IDS icon slugs** and the matching SVGs under `assets/icons/`. Color the icon with the variant tokens from **Tokens** / **States** (do not bake fixed fills into the asset if the SVG supports `currentColor`).

| Variant | Icon slug | Asset file (repo root) |
|---|---|---|
| Info | `info-circ-solid` | `assets/icons/info-circ-solid.svg` |
| Success | `status-ok-circ-solid` | `assets/icons/status-ok-circ-solid.svg` |
| Minor / warning | `status-warn-tri-solid` | `assets/icons/status-warn-tri-solid.svg` |
| Major | `status-error-diamond-solid` | `assets/icons/status-error-diamond-solid.svg` |
| Critical | `status-critical-square-solid` | `assets/icons/status-critical-square-solid.svg` |
| Close action | `shape-x` | `assets/icons/shape-x.svg` |

**Density variants (optional):** the same folder may include `-16` or `-ko` suffixes (e.g. `info-circ-solid-16.svg`); use the base `*.svg` unless the target density explicitly requires another file.

### Code generation & bundling

When generating Toast (or any component that references these icons) for **any framework** (React, Angular, Vue, Lit, etc.):

- Include the **`assets/icons`** directory in the application bundle (or copy the referenced SVGs into the framework’s static/public assets with stable URLs).
- Resolve icon paths relative to the repo root as documented above, or map slugs to your bundler’s asset pipeline (e.g. import URL, `angular.json` assets, Vite `public/`, etc.).
- Do not substitute ad-hoc inline paths; keep slug → file mapping aligned with this table so design and implementation stay consistent.

## Layout & Measurements

### Core geometry (from reviewed frame)
- Toast height: `48px`.
- Toast without link: `516x48`.
- Toast with link: `617x48`.
- Root padding: vertical `14px`, horizontal `24px`.
- Root spacing:
  - alert icon to description: `8px`
  - content-to-actions: `32px`
  - link-to-close gap: `32px`
- Corner radius: `8px`.
- Border width: `1px`.

### Content layout
- One-line message body in white text.
- Left icon block aligns center vertically in the `48px` row.
- Action container is right aligned and contains:
  - optional link text (no trailing icon)
  - optional close icon (`shape-x`, `12x12`, color `var(--color-icon-white)`)

### Variant matrix captured in Figma
- Alerting types (5): `Info`, `Success`, `Minor`, `Major`, `Critical`.
- Link option (boolean): `Show View Details = false | true`.
- Closable option: close action is present in reviewed variants and remains part of the runtime contract as an optional action.

## Interactions

- **Toast lifecycle**:
  - Appears in viewport stack.
  - Auto-dismiss timeout is supported by runtime provider.
  - Hover/focus should pause dismissal when runtime supports pause behavior.
- **Link option** (`Show View Details`):
  - When enabled, link action is visible and keyboard focusable.
  - Link action triggers navigation/details callback; toast remains unless explicitly dismissed by app logic.
- **Closable option**:
  - Close action is keyboard and pointer accessible.
  - Close action immediately removes the toast instance from stack.
- **Accessibility**:
  - Use `role="status"` for informational/success/minor/major and `role="alert"` for critical when urgency requires assertive announcement.
  - Keep `aria-atomic="true"` on each toast item.

## Composition & API (runtime)

- `variant?: "info" | "success" | "minor" | "major" | "critical"` (default `info`).
- `message: string | ReactNode`.
- `showLink?: boolean` (maps to "View Details" action visibility).
- `onLinkClick?: () => void`.
- `closable?: boolean` (default `true`).
- `onClose?: () => void`.
- `duration?: number` (auto-dismiss timeout; optional override).

## Codegen Contract (Framework-Agnostic Blueprint)

This section is normative for code generation. If any statement here conflicts with examples or implementation notes, this section wins.

### 1) Deterministic structure (slot schema)

Required slot order in each toast item:

1. `root`
2. `alertIcon`
3. `message`
4. `linkAction` (optional)
5. `closeAction` (optional)

Canonical structure:

- `viewport`
  - `root` (one per toast instance)
    - `alertIcon`
    - `message`
    - `linkAction` (if `showLink=true`)
    - `closeAction` (if `closable=true`)

Slot requirements:

- `root` must be a single-row container.
- `message` is required for all variants.
- `linkAction` and `closeAction` are independently optional.
- `closeAction` uses `shape-x` visual (`12x12`) centered in a `24x24` hit target.

### 2) Variant and option matrix

Supported variants:

- `info`
- `success`
- `minor`
- `major`
- `critical`

Supported options:

- `showLink: boolean`
- `closable: boolean`

Supported combinations:

- `5 variants x 2 link states x 2 close states = 20` valid combinations.

### 3) Per-slot style contract (tokenized)

#### Root

- Height: `48px`
- Padding: `var(--padding-padding-14)` (block), `var(--padding-padding-24)` (inline)
- Radius: `var(--corner-radius-radius-8)`
- Border: `var(--border-width-border-1) solid var(--color-border-white)`
- Background: `var(--color-static-gray-900)`
- Gap (`alertIcon` to `message`): `var(--spacing-space-8)`

#### Alert icon

- Size: `20x20`
- Asset by variant:
  - `info-circ-solid`
  - `status-ok-circ-solid`
  - `status-warn-tri-solid`
  - `status-error-diamond-solid`
  - `status-critical-square-solid`
- Color by variant:
  - info: `var(--alert-blue-500)`
  - success: `var(--alert-green-500)`
  - minor: `var(--alert-yellow-800)` (with layered yellow token support when applicable)
  - major: `var(--color-border-alerting-major-major)`
  - critical: `var(--alert-red-500)`

#### Message

- Typography: body-2 scale (`var(--font-size-body-2)`), line-height `var(--font-line-height-line-height-18)`
- Color: `var(--color-static-gray-white)`
- Overflow behavior:
  - single-line in default demo state
  - framework may wrap for narrow containers unless product explicitly enforces truncation

#### Link action

- Text only (no trailing icon)
- Color: `var(--color-text-white)`
- Underlined
- Keyboard focusable

#### Close action

- Hit target: `24x24`
- Icon glyph: `shape-x`
- Icon size: `12x12`
- Icon color: `var(--color-icon-white)`
- Keyboard focus ring: `var(--border-width-border-2) solid var(--color-border-brand-base)`

### 4) Behavior contract

- Default auto-dismiss duration: `5000ms`.
- `duration=0` disables auto-dismiss.
- If runtime supports hover/focus pause, timer pauses while hovered/focused and resumes on leave/blur.
- `showLink=true` shows actionable link text.
- `closable=true` shows dismiss control and removes toast on activation.
- `closable=false` must remove close action slot entirely (not visually hidden interactive control).

### 5) Accessibility contract

- Toast container uses:
  - `role="status"` for `info|success|minor|major`
  - `role="alert"` for `critical` when assertive announcement is needed
- `aria-atomic="true"` per toast item.
- `closeAction` has accessible name (e.g., "Close").
- `linkAction` must be focusable and announced as a link/button per framework semantics.

### 6) Asset resolution and bundling contract

- Icon slugs resolve to files under `assets/icons`.
- Code generators must ensure these assets are included in final app bundle (copy/static/public/import pipeline depending on framework).
- Slug-to-file mapping must remain stable and centralized; no ad-hoc icon substitution.
- If an asset is missing, generator must fail loudly (build-time warning/error), not silently substitute a different icon.

### 7) Fallback and error rules

- If `variant` is unknown, fallback to `info`.
- If token is missing, generator may apply the token fallback chain but must report the missing token.
- If both `showLink=false` and `closable=false`, toast still renders `alertIcon + message`.

### 8) Validation checklist (must-pass)

- [ ] All 5 variants render correct icon slug and color token.
- [ ] `showLink` toggles link action without layout break.
- [ ] `closable` toggles close action without layout break.
- [ ] Close icon is `shape-x`, `12x12`, with `var(--color-icon-white)`.
- [ ] Gap between alert icon and message equals `8px`.
- [ ] Root dimensions and tokenized styles match contract.
- [ ] Auto-dismiss default is `5000ms` (unless explicitly overridden).
- [ ] Accessibility roles/labels match variant rules.
