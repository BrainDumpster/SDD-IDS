## Anatomy
Deterministic slot order:
1. `root`
2. `leadingIconSlot`
3. `inputViewport`
4. `inputText`
5. `caret` (optional; shown in `typing` and `filled`)
6. `clearButtonSlot` (optional; shown in `typing` and `filled`)
7. `focusRing` (optional; shown in `focus`)

Notes:
- `leadingIconSlot` uses the search icon (`16x16`) and stays visible in all documented states.
- `inputViewport` expands to fill remaining horizontal width.
- `focusRing` is a sibling overlay rectangle around `root`, not a border replacement.
- Input semantics (caret behavior, value editing model, and text field accessibility expectations) follow the textbox baseline in `components/ids/text-box/design-spec.mdx`, but Figma Search states/tokens remain the source of truth when there is any conflict.

## Interactions
- Input is text-editable in all documented Figma states (`default`, `hover`, `typing`, `filled`, `focus`).
- `focus` adds a dedicated outer ring slot (`focusRing`) while preserving base border.
- `typing` begins when input receives non-empty text; caret is shown.
- `filled` keeps typed value and clear button visible.
- Clear icon must appear whenever input value is non-empty.
- Clear action removes value and returns to `default` (if blurred) or `focus` (if still focused).
- Hover changes only border emphasis; it does not alter value text token.
- Keyboard:
  - `Tab` enters/leaves control.
  - `Enter` dispatches search submit event with current query.
  - `Escape` clears active query when value is non-empty.

## Composition & API (runtime)
Required runtime inputs:
- `value?: string`
- `defaultValue?: string`
- `onValueChange?: (value: string) => void`
- `onSearch?: (value: string) => void`
- `placeholder?: string` (default `"Search"`)
- `size?: "large" | "small"` (default `"large"`)
- `showClearButton?: boolean` (default `true`)
- `aria-label?: string`
- `aria-describedby?: string`
- `id?: string`
- `name?: string`

Runtime outputs:
- `onValueChange` fires after every user text mutation.
- `onSearch` fires on `Enter` or explicit search action.
- Clear button action emits `onValueChange("")`.

Controlled/uncontrolled rule:
- If `value` is provided, component is controlled and internal state must not diverge.
- If `value` is omitted, component is uncontrolled and initializes from `defaultValue`.

## Codegen Contract (Framework-Agnostic Blueprint)
Deterministic rendering schema:
- Always render slots in anatomy order.
- Only render `clearButtonSlot` when value is non-empty and `showClearButton=true`.
- Only render `caret` in `typing` and `filled` visual states.
- Only render `focusRing` when `state=focus`.

Variant/option matrix:
- `size`: `large | small`
- `state`: `default | hover | typing | filled | focus`
- `hasValue`: `false | true`

Per-slot style contract:
- `root`
  - horizontal layout, fixed height by `size`, border width `var(--border-width-border-default)`
  - default/typing/filled/focus border: `var(--color-border-accessible)`
  - hover border: `var(--color-border-strong)`
- `leadingIconSlot`
  - icon asset: `search-16` (`16x16`)
  - all states token: `var(--color-icon-brand-base)`
- `inputText`
  - placeholder token: `var(--color-text-disabled)`
  - typed value token: `var(--color-text-neutral)`
  - typography: `var(--font-size-body-2)` / `var(--font-line-height-line-height-20)`
- `caret`
  - stroke color: `var(--color-border-strong)`
  - stroke width: `var(--border-width-border-default)`
- `clearButtonSlot`
  - icon asset: `ctrl-close-16` (`16x16`)
  - icon token: `var(--color-icon-accessible)`
- `focusRing`
  - `1px` border using `var(--color-border-brand-base)`
  - geometry must exceed root bounds (outer rectangle)

Behavior contract:
- Value transitions:
  - empty + no focus -> `default`
  - empty + focus -> `focus`
  - non-empty + editing -> `typing`
  - non-empty + stable -> `filled`
- Clear-button visibility transition:
  - empty value -> clear button hidden
  - non-empty value -> clear button visible
- `hover` is additive to pointer hover and overrides border token only.

Accessibility contract:
- Render as native search input (`type="search"`) or equivalent combobox/textbox primitive.
- Must expose accessible name through visible label context or `aria-label`.
- Clear control must have an accessible label (for example: "Clear search").
- Preserve keyboard operability for input and clear action.

Asset resolution and bundling:
- Required icons:
  - `search-16` (`16x16`) for `leadingIconSlot`
  - `ctrl-close-16` (`16x16`) for `clearButtonSlot`
- Required icon color bindings for code generation:
  - `search-16` MUST always render with `var(--color-icon-brand-base)` in all states.
  - `ctrl-close-16` MUST render with `var(--color-icon-accessible)` when visible.
- Icons must resolve from the Synapse icon package/registry, not inline hardcoded SVG literals in generated templates.

Fallback and error rules:
- Unknown `size` -> fallback to `large`.
- Unknown visual state hint -> fallback to `default` or derived runtime state from value/focus.
- Missing icon asset -> render slot with reserved space and log generator warning.
- Missing required text token -> fallback to nearest semantic category (`disabled` for placeholder, `neutral` for value) and emit warning.
- Unsupported `disabled` input (if passed by host app) -> ignore and keep Figma-documented interactive behavior; emit warning in generator diagnostics.

Validation checklist:
- [ ] Slot order matches anatomy.
- [ ] `large` and `small` keep heights `40px` and `32px`.
- [ ] Hover only changes border token.
- [ ] Focus-visible renders outer ring in addition to base border.
- [ ] Typing/filled states show clear button and caret.
- [ ] Placeholder/value text tokens switch correctly by empty vs non-empty value.
- [ ] `search-16` uses `var(--color-icon-brand-base)` in every state.
- [ ] `ctrl-close-16` uses `var(--color-icon-accessible)` when shown.
- [ ] Light and dark state tables remain structurally parallel.
