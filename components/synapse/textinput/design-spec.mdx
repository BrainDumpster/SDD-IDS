## Layout & Measurements
- Runtime width is container-driven (`width: 100%`), while Figma sample width is `300px`.
- Vertical rhythm:
  - field stack gap: `var(--spacing-space-4)` (`4px`)
  - helper/error row gap: `var(--spacing-space-8)` (`8px`) when icon + text are present.
- Control heights:
  - `Size=Large` control height: `40px`
  - `Size=Small` control height: `32px`
- Text Input frame heights (including helper row):
  - `Large`: `64px`
  - `Small`: `56px`
- Text Area variant uses same token model but taller body (Figma sample: `150px` total frame).
- Control paddings:
  - horizontal: `var(--padding-padding-16)`
  - inner content gap: `var(--spacing-space-10)`
- Radius: `var(--corner-radius-radius-4)`
- Border width: `var(--border-width-border-1)`
- Suffix and status icons: `16px`

## Interactions
- Pointer:
  - hover moves border to `var(--color-border-strong)` unless disabled/error.
  - click/tap focuses control and enters selected/focus styling.
- Keyboard:
  - `Tab` focuses control.
  - `Shift+Tab` moves to previous focusable control.
  - Text input behavior (`Arrow`, `Home`, `End`, typing, selection, delete/backspace) follows native input/textarea semantics.
- Focus:
  - `focus-visible` must render explicit outer indicator using brand border token.
- Error:
  - error visuals persist until validation state clears.
- Disabled:
  - blocks editing, pointer interaction, and focus.

## Codegen Contract (Framework-Agnostic Blueprint)
Deterministic structure:
- `TextInputRoot`
  - `TextInputField`
    - optional `TextInputLabel`
    - `TextInputControl`
      - `TextInputValueSlot` (`input` or `textarea`)
      - optional `TextInputSuffixIcon`
    - optional `TextInputHelperRow`
      - optional `TextInputErrorIcon`
      - `TextInputHelperText` (helper or error text)

Variant matrix:
- `type`: `text-input | text-area`
- `size`: `large | small`
- `content`: `empty | filled` (derived from value)
- `state`: `default | hover | selected | focus | disabled | error`
- boolean options: `showLabel`, `showHelperText`, `showIcon`, `required`

Per-slot style contract:
- Control always uses tokenized background/border/radius/padding; never hardcoded colors.
- Selected/focus states must use `var(--color-border-brand-base)`.
- Error state must use alerting critical border + error row (icon + text) when `errorText` exists.
- Disabled state uses gray-light surface and disabled text token.

Behavior contract:
- `state` prop is visual-forcing only; runtime interaction still follows native input behavior unless `disabled`.
- `invalid=true` or non-empty `errorText` activates error styling.
- `type="text-area"` swaps slot element to multiline input and keeps same token model.

Accessibility contract:
- Use native `<input>` / `<textarea>` semantics.
- `aria-invalid="true"` when invalid/error.
- `aria-describedby` references helper/error text node id when present.
- Required indicator (`*`) is visual; required semantics must be on input element.

Asset and icon contract:
- Prefer framework `Icon` component first.
- Pass icon name through actual icon prop (`name`/`shape`/`icon`/`glyph` depending on framework).
- Default suffix icon from this Figma sample is `mail`.
- Error icon maps to critical status icon tokenized in color; raw SVG fallback only when icon component is unavailable.

Fallback/error rules:
- Unknown `size` -> fallback `large`.
- Unknown `type` -> fallback `text-input`.
- Unknown `state` -> fallback `default`.
- If `showIcon=true` and `iconName` missing, use default `mail`.
- If `invalid=true` and `errorText` missing, render border error state without error row text.

Validation checklist:
- [ ] All state colors/borders come from semantic tokens.
- [ ] Large/small control heights match `40px/32px`.
- [ ] `text-input` and `text-area` both generated from same contract.
- [ ] Disabled blocks interaction and focus.
- [ ] Error styling and helper row behavior are deterministic.
- [ ] Accessibility attributes are emitted (`aria-invalid`, `aria-describedby`, required semantics).
