- Verified from updated Figma slider area (`node-id=43799-178868`) and slider instances.
- Slider main instance width in sample frame: `477px` (reference only; implementation should be container-driven).
- Slider main height in sample frame: `32px`.
- Track height: `4px`.
- Stepper size: `8px` (dot marker).
- Marker/thumb size in component parts: `16px x 16px`.
- Runtime width behavior: slider should sync to parent width (`width: 100%`, `box-sizing: border-box`).
- Label layout: when `showLable=true`, render labels inline as `<min label> <slider track> <max label>` (not above the track).

## Interactions
- Clicking on track updates slider value to nearest valid step position.
- Dragging thumb updates value continuously (or step-wise when `step` is defined).
- In range mode, min-thumb and max-thumb drag independently (no pointer-capture conflict between thumbs).
- In range mode, thumbs do not cross: min value is constrained to `<=` max value, max is constrained to `>=` min value.
- Keyboard support: Arrow keys for increment/decrement, Home/End for min/max.
- Disabled state blocks pointer and keyboard interactions.
- Optional steppers (`showTicks` / `showStepper`) render on the slider track based on the configured `step` interval.
- Stepper visual states:
  - Selected steppers (at or below current value, or inside selected range) use `var(--color-icon-brand-base)`.
  - Unselected steppers use component/neutral surface + disabled border tokens.
  - Steppers are dot markers on track (no numeric tick labels).
  - Steppers include both end points (`min` and `max`).
  - Selected steppers are solid (no extra outer ring treatment).
  - Stepper dots are center-aligned to thumb travel path (including endpoint inset).
- Optional labels (`showLable`) are display controls and do not change value semantics.
- When labels are shown, min/max labels are placed at track edges in the same row as the track.
- Selected value labels are displayed below thumb(s) for both single-value and range sliders.
- Value labels align to thumb centerline and render below the thumb with clear vertical separation.
- Stepper and value-label placement use the same thumb-travel geometry (including thumb-radius endpoint offsets) to avoid edge drift.
- Stepper dots are vertically centered on the track centerline.
- In range mode, both thumbs are vertically centered on the same track centerline.
- Stepper horizontal placement follows track endpoints (`0%` to `100%`), with explicit first/last endpoint anchoring.
- In disabled state, value-under-thumb text uses `var(--color-text-disabled)`.

## Component API
Use this API contract in generated component code when user requests implementation:

| Property | Type | Default | Description |
|---|---|---|---|
| `min` | `number` | *(required by consumer or component default policy)* | Minimum slider value. |
| `max` | `number` | *(required by consumer or component default policy)* | Maximum slider value. |
| `value` | `string \\| number \\| (string \\| number)[]` | `''` | Current value. Supports scalar or range-array representations. |
| `disabled` | `boolean` | `false` | Disables interaction and applies disabled styling/state. |
| `customLabel` | `string[]` | `[]` | Custom label list for replacing default labels. |
| `showLable` | `boolean` | `false` | Show labels for slider values (kept as requested API name). |
| `showTicks` | `boolean` | `false` | Show ticks on track based on `step` configuration. |
| `showStepper` | `boolean` | `false` | Alias for `showTicks`; renders stepper points on track. |
| `step` | `number` | *(implementation default policy)* | Gap between adjacent slider values. |
| `showValueInput` | `boolean` | `false` | Show end value input box(es) near slider. |

## Events
- Emits `onValueChange` with payload type `number | string`.
- Emit on pointer/keyboard/value-input updates when effective value changes.

## Disabled Input Styling
- Disabled value input text: `var(--color-text-disabled)`
- Disabled value input border: `var(--color-border-accessible)`
- Disabled value input background: `var(--color-background-gray-light)`

## Accessibility
- Use proper slider semantics (`role="slider"` or native range input equivalent per framework).
- Keep `aria-valuemin`, `aria-valuemax`, `aria-valuenow` synchronized.
- Provide visible focus indicator and keyboard operability.
- Ensure disabled state is announced and non-interactive.

## Variants
- Single value slider
- Range slider (when `value` uses array form)
- Disabled slider
- Slider with labels/ticks/value input

## Behavior & Guidelines
- Use for bounded numeric/string value selection where drag + keyboard are expected.
- Keep `min`, `max`, `step`, and `value` consistent (clamp/normalize invalid values).
- For range mode, ensure ordered values and non-crossing behavior (or document crossing policy).
- Keep styling token-driven; no hardcoded visual values in implementation code.

## Token Gaps / Notes
- Prefer semantic tokens from `theme.css` and this spec.
- Avoid raw palette token usage in component code when semantic tokens exist.
- If additional slider-specific semantic tokens are introduced, add them to this section and update state tables.
