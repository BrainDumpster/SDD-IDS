## Overview

- A button is a designated clickable area that uses color, text, and/or icons to indicate the action it performs. It allows users to initiate or complete a task. Place buttons where they are easy to find or where users expect to see them. ## Purpose & Usage

- Destructive buttons should not be used for reversible actions
- Overuse can increase confusion, frustration, and clutter on the screen
- Ensure consistent placement of destructive buttons
- Use a clear label (e.g., ‘Delete’, see above) to describe an irreversible action, instead of ‘OK’ or ‘Confirm’
- Buttons should have a concise and descriptive label to provide clear guidance to the user.
- Button labels need to be short, preferably one or two words.
- Button labels are title case. For example, labels could be ‘Submit Order’, ‘File Search’, or ‘Manage License’.
- Button labels should correspond to the actions they perform. Use a clear label (e.g., ‘Delete’, see above) to describe an irreversible action, instead of ‘OK’ or ‘Confirm’.
- The labels on buttons should not be a brand name.
- The labels on buttons should not contain any post-prepositions or articles such as ‘a’, ‘an’, or ‘the’.
- Avoid using punctuation within button labels.
- Use verbs for buttons rather than yes or no to make buttons more user-friendly and glanceable, and leave less room for misinterpretation. For example, ‘Submit, ‘Cancel’, ‘Save’, ‘Search’ or ‘Apply’.
- Do not use all caps for button labels. If there is no fitting action text, ‘OK’ is acceptable.

- Button order:
- (from left to right) Add, Edit, Delete, More Actions, Export

- Apply the same style to buttons that are in close proximity and of equal importance.
- Use primary buttons for main actions or more commonly performed actions on a page, form, or data grid. When buttons are left-aligned, place primary button(s) first.
- Use secondary buttons for actions that are not the main focus on the page or a form. For example, within a wizard, ‘Next’ is the primary button and ‘Back’ is the secondary button because ‘Back’ is not the main action.
- Disabled buttons should be accompanied with a tooltip to guide users on what needs to be done to enable the button. When permissions are required to enable a button, show the button only when a user has the appropriate permissions. For example, a user can enable a button by filling out the required fields in a form, or by selecting a few rows in the data grid, or changing a certain setting within the application. If a button is permanently disabled for a user, it’s usually better not to show it at all to create an intuitive and secure UI.

- The action/label of this type of button can be switched out based on item selection. For example, within a data grid, the same button can be used to represent actions ‘Acknowledged’ and/or ‘Unacknowledged’. The label is determined by current item selection.
- This type of button should not be confused with a toggle switch. Changes made using a toggle switch might affect the whole page or the application, but a binary button only affects selections within a data grid.
- Icon buttons may be used when space is limited and if icons are universally recognized. For example, a trash can icon for a delete action, or a pencil icon for an edit action.

## Typography

- Default buttons may contain a label or an icon, but not both. They can exhibit one of four distinct styles: Primary, Secondary, Tertiary, or Destructive. A stand alone tertiary button that resembles a link is the only instance when an icon and text may be suitable. Each style serves a unique purpose and provides a different visual cue to the user.
- Dropdown button menus serve to present a collection of actions that can be executed on a specific data set. An example of this is the ‘More Actions’ dropdown menu in a data grid, which reveals a list of potential actions that can be performed on the data within the grid. Once an action from the list is selected the dropdown menu automatically closes. Dropdown menu also closes when a click is registered outside the dropdown menu or when the ‘Esc’ key is pressed. Dropdown menus are available in three distinct styles: Primary, Secondary, and Tertiary, each offering a different visual emphasis.

## Height

- Large - Large buttons are 40px in height, and the default
      padding on the left and the right is 16px. These are used in most places,
      including modal dialogs. padding on the top and bottom is 6px.
- Medium - Medium buttons are 32px in height, and the
      default padding on the left and right is 16px. padding on the top and bottom is 6px. They are used in places

- Small - Small buttons are 24px in height, and the default
      padding on the left and right is 16px. padding on the top and bottom is 2px. The text is 13pt for small buttons
      only. They are used in places where the other sizes wouldn't fit, but
      where it is important to include a button shape. This could include small
      inline alerts with actions, or inside a table row.
- Example: Different button sizes with respect to height (40px, 32px and
      24px). Icon buttons are available only in two sizes.

<!-- ds:section id=dynamic-primary -->
## Primary

- Primary buttons have the strongest visual weight of all buttons
- The purpose of primary buttons are to call the user's attention to the most important actions on the screen
- Some examples of primary actions may include: ‘Apply’, ‘Add’, and, ‘Edit’ but this is not a complete list

<!-- ds:section id=dynamic-secondary -->
## Secondary

- They are used to indicate actions that compliment primary actions or to offer high contrast between primary actions and less important tasks
- Use secondary button sparingly
- Some examples of placement for secondary buttons are within cards, modals, and wizards

<!-- ds:section id=dynamic-tertiary -->
## Tertiary

- Tertiary buttons have the weakest visual weight of all three button styles
- They are used for actions that do not require the user’s focus
- Buttons like ‘Skip’ and ‘Cancel’ are usually tertiary style buttons
- A stand alone tertiary button that resembles a link is the only instance when both an icon and text may be suitable

      be less than 56px
- Max - The maximum width of a button (with text) should not
      be more than 320px
- Different button sizes with respect to width (56px and 320px).
