## Anatomy
- Wizard container (inline, no overlay)
- Step indicator/progress bar
- Step header with title and subtitle
- Step content area
- Navigation buttons (Previous, Next, Cancel, Finish)
- Focus ring for keyboard navigation
- Step validation indicators
- Optional step summary

## Layout & Measurements
- Standard width: 100% of container
- Step indicator height: 40px
- Header padding: 24px
- Body padding: 24px
- Footer padding: 16px 24px
- Button spacing: 8px
- Border radius: 8px
- Focus ring: 2px offset from element
- Minimum height: 400px
- Compact density: 36px for compact mode

## States (Dark Theme)
- Uses semantic tokens that automatically adapt to dark theme
- Surface tokens: `var(--color-background-surface-1)` (#f4f4f4)
- Text and border colors remain consistent via semantic variables
- Step indicators maintain visibility in dark theme
- Buttons adapt to dark theme

## Interactions
- Click Previous/Next/Finish buttons to navigate steps
- Click step indicators to jump to completed steps
- Hover provides visual feedback on buttons
- Focus ring uses brand color for keyboard navigation
- Step validation prevents navigation to invalid steps
- Keyboard navigation: Tab to navigate, Enter to confirm
- Inline behavior - no overlay, part of page flow

## Accessibility
- Focus ring: 2px brand color border
- Keyboard navigation: Tab, Enter, Arrow keys
- Screen reader support: Proper ARIA attributes for wizard steps
- High contrast: Meets WCAG AA standards with provided colors
- Semantic HTML: Use proper landmarks and roles
- Focus management: Logical tab order through wizard
- Step announcements: Screen reader announces current step

## Variants
- **Default**: Standard inline wizard
- **Linear**: Sequential steps, no skipping
- **Non-linear**: Can jump between completed steps
- **Validation**: With step validation indicators
- **Progress**: With progress bar instead of steps
- **Compact**: Reduced size for space-constrained interfaces
- **With Summary**: With step summary section
- **Auto-save**: Automatically saves progress

## Behavior & Guidelines
- Use inline wizards for multi-step processes within page flow
- Provide clear step descriptions and progress indication
- Allow navigation between completed steps when appropriate
- Implement proper validation for each step
- Show clear completion state and confirmation
- Test with screen readers for proper step announcement
- Consider responsive behavior for mobile devices
- Use consistent styling across wizard variants
