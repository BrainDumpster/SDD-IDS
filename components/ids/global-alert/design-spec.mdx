## Anatomy

Deterministic slot order:
1. `GlobalAlertRoot`
2. optional `CarouselRail`
   - `CarouselPreviousButton`
   - `CarouselCount`
   - `CarouselNextButton`
3. `ContentRow`
   - `LeadingStatusIcon`
   - `Message`
   - optional `InlineLink`
4. `ActionsRow`
   - optional `ActionButton`
   - optional `DismissButton`

Notes:
- `Message` and `InlineLink` are part of the same reading flow.
- `DismissButton` is absent in the critical, no-action configuration shown in Figma.
- `ActionButton` and `DismissButton` can coexist.

## Layout & Measurements

- Root width in Figma examples: `1300px` sample; runtime width is container-driven (`width: 100%`).
- Root minimum height: `40px`.
- Root left padding without carousel: `var(--padding-padding-20)`.
- Root left padding with carousel: `0` (carousel rail is the leading flex child; do not reserve a fixed pixel inset that can drift from measured rail width).
- Spacing between carousel rail trailing edge and leading status icon: `var(--spacing-space-16)` (in addition to the root flex `gap` between major regions).
- Content row vertical padding: `var(--padding-padding-10)`.
- Content row gap: `var(--spacing-space-8)`.
- Status icon size: `16px x 16px`.
- Actions row padding: `var(--padding-padding-8) var(--padding-padding-16)`.
- Actions row gap when action present: `var(--spacing-space-16)`.
- Dismiss/chevron icon size: `12px x 12px`.
- Carousel rail padding: `var(--padding-padding-10) var(--padding-padding-14)`.
- Carousel rail content gap: `22px`.
- Carousel chevron color: must match carousel count text contrast (white chevrons on `critical`, `warning-major`, and `informational` rails; black chevrons on `warning-minor` rail). Source SVGs may be neutral gray; implementations may tint via `filter` or equivalent so chevrons are not mid-gray on dark rails.
- Action button horizontal padding: `16px`.
- Action button vertical padding: `2px`.
- Action button radius: `2px`.
- Action button border width: `1px`.

Runtime layout rules:
- Root is a full-width banner and must not wrap into multiple stacked rows.
- `CarouselRail` is a leading in-flow flex child and spans the full banner height (stretch).
- `ContentRow` grows to consume available width between the carousel rail (when present) and the actions row.
- `ActionsRow` is always right aligned.
- Long message text may wrap, but action and dismiss controls remain right aligned.

## Interactions

- `DismissButton` emits `onDismiss` and removes the banner from the current render tree.
- `ActionButton` emits `onAction` when activated by click, `Enter`, or `Space`.
- `InlineLink` emits `onLinkClick` when present; if `linkHref` is also provided, host navigation behavior should proceed unless prevented.
- `CarouselPreviousButton` emits `onPrevious`.
- `CarouselNextButton` emits `onNext`.
- `showCarousel=true` only changes layout and exposes navigation controls; **the component does not own the alert-item list or the active index**. The host application (or a thin wrapper) must:
  - Store an ordered list of alert payloads (at minimum the string shown as `message`, plus any per-item link/action overrides if the product requires them).
  - Derive `carousel.currentItem` as **1-based** index into that list for the active item.
  - Set `carousel.totalItems` to the list length (minimum `1` for a stable counter).
  - Update the active index when `onPrevious` / `onNext` fire; wrapping at the ends vs clamping is **host-defined** (Storybook examples use wrap-around for demo usability).
  - Pass the active item’s copy as `message` (and optional `linkLabel` / `actionLabel` if they vary per item).
- `showAction=true` never suppresses dismiss affordance.
- Figma shows `critical` without action as non-dismissible by default; all other documented default variants include dismiss control.

**Storybook (reference implementation):** `GlobalAlert.stories.tsx` includes `CarouselInteractive` and `CarouselInteractiveInformational`, which keep `items[]` in React state, wire `onPrevious` / `onNext`, and expose **Add alert item** / **Remove current item** so carousel behavior can be exercised without hard-coded static `currentItem` / `totalItems` only.

## Composition & API (runtime)

Required inputs:
- `message: string`

Optional inputs:
- `severity?: "critical" | "warning-major" | "warning-minor" | "informational"`
- `linkLabel?: string`
- `linkHref?: string`
- `onLinkClick?: () => void`
- `actionLabel?: string`
- `onAction?: () => void`
- `dismissible?: boolean`
- `onDismiss?: () => void`
- `carousel?: { currentItem: number; totalItems: number; onPrevious?: () => void; onNext?: () => void }`

**Multi-item carousel (host pattern):** the public API stays flat (`message` + `carousel` counter + callbacks). For N user-supplied alerts, the host keeps `alerts: AlertPayload[]`, `activeIndex: number` (0-based internally), and passes:
- `message = alerts[activeIndex].message` (and per-item link/action fields if modeled).
- `carousel = { currentItem: activeIndex + 1, totalItems: alerts.length, onPrevious, onNext }` with handlers that update `activeIndex` (and optionally remove items from `alerts`).

Runtime rules:
- `linkLabel` without `linkHref` still renders an interactive inline control and relies on `onLinkClick`.
- `actionLabel` without `onAction` still renders a button; host may attach behavior later.
- `dismissible` defaults to `false` for `critical` without action and `true` otherwise.
- `carousel.currentItem` is **1-based** in the visible counter (`"k of N"`).

## Codegen Contract (Framework-Agnostic Blueprint)

Deterministic slot schema:
- `GlobalAlertRoot`
  - optional `CarouselRail`
    - `CarouselPreviousButton`
    - `CarouselCount`
    - `CarouselNextButton`
  - `ContentRow`
    - `LeadingStatusIcon`
    - `Message`
    - optional `InlineLink`
  - `ActionsRow`
    - optional `ActionButton`
    - optional `DismissButton`

Supported matrix:
- `severity`: `critical | warning-major | warning-minor | informational`
- `showLink`: derived from `linkLabel`
- `showAction`: derived from `actionLabel`
- `showCarousel`: derived from `carousel`
- Full valid matrix is all 32 combinations from Figma.

Per-slot style contract:
- Root fills container width and uses severity surface tokens only.
- `CarouselRail` background uses the severity **strong** background token only (no hardcoded hex fallbacks): `var(--color-background-alerting-critical-strong)` | `var(--color-background-alerting-major-strong)` | `var(--color-background-alerting-minor-strong)` | `var(--color-background-alerting-info-strong)` matching `critical` | `warning-major` | `warning-minor` | `informational`.
- `CarouselRail` is a **leading in-flow** flex child (full-height stretch), not an absolutely positioned overlay; root must not rely on a fixed `padding-left` inset to “guess” rail width—spacing before `LeadingStatusIcon` uses rail `margin-inline-end: var(--spacing-space-16)` plus the root flex `gap`.
- Carousel chevron assets may encode neutral gray fills; implementations must tint chevrons to match rail/count contrast (white on `critical` / `warning-major` / `informational`; black on `warning-minor`).
- `LeadingStatusIcon` uses canonical shape names:
  - `critical` -> `status-critical-square` (`16x16`, color `var(--color-icon-alerting-critical)`)
  - `warning-major` -> `status-error-diamond`
    (`16x16`, color `var(--color-icon-alerting-major)`)
  - `warning-minor` -> `status-warn-tri` (`16x16`, color `var(--color-icon-black)`)
  - `informational` -> `info-circ` (`16x16`, color `var(--color-icon-alerting-info)`)
- `DismissButton` uses `shape-x`; icon color is `var(--color-icon-white)` for informational and `var(--color-icon-black)` for all other severities.
- `InlineLink` and `ActionButton` inherit severity foreground color.
- `ActionButton` is outlined only; no filled variant is shown in Figma.

Behavior contract:
- Component is presentational plus event-emitting only; it does **not** manage carousel index, item collection, or navigation—only emits `onPrevious` / `onNext` when the user activates the carousel controls (disabled state for those buttons is host-defined if the product requires it; default Storybook wiring always calls handlers).
- `onAction`, `onDismiss`, `onPrevious`, `onNext`, and `onLinkClick` are emitted independently.
- Dismiss action hides the alert only in demo/story contexts unless host chooses controlled behavior.

Accessibility contract:
- Root uses `role="alert"` and assertive live region behavior.
- Dismiss, action, link, and carousel controls are keyboard reachable.
- Buttons expose accessible labels:
  - dismiss: `Dismiss alert`
  - previous: `Previous alert`
  - next: `Next alert`
- Counter text remains programmatically readable, e.g. `1 of 4`.

Asset resolution + bundling contract:
- Storybook reference uses the shared `Icon` component with `shapeName` set to the canonical slugs below and `variant="img"` for full-color SVG rendering on alert surfaces. `Icon` resolves `assets/icons/<slug>.svg` via Vite `import.meta.glob(..., { query: '?url' })` so bundled URLs are file URLs, not `data:image/svg+xml`.
- Default `Icon` variant for other surfaces (e.g. navigation) remains `mask` (CSS mask + `currentColor`); alerts use `img` only where multi-hue glyphs or `filter`-based chevron tinting is required.
- Do not ship inline `<svg>` trees or custom “fallback shape” renderers inside application code; missing slugs render as an empty placeholder until assets exist.
- Canonical icon names (codegen / spec names):
  - `info-circ`
  - `status-critical-square`
  - `status-error-diamond`
  - `status-warn-tri`
  - `shape-x`
  - `chev-left-16`
  - `chev-right-16`
- If a destination app uses a different icon package, map these slugs to that library’s components while preserving the same `shapeName` contract.

Fallback/error rules:
- Unknown `severity` -> fallback to `critical`.
- `carousel.totalItems < 1` -> render `1 of 1`.
- `carousel.currentItem < 1` -> clamp to `1`.
- `linkLabel` missing -> no link rendered.
- `actionLabel` missing -> no action button rendered.

Validation checklist:
- [ ] All 32 documented Figma combinations can be represented by API inputs.
- [ ] `onAction` is emitted when action button is activated.
- [ ] `onPrevious` / `onNext` are emitted when carousel buttons are activated and host updates `message` + `currentItem` + `totalItems` for multi-item flows.
- [ ] `critical` without action defaults to non-dismissible behavior.
- [ ] Severity-specific foreground color flips to black only for `warning-minor`.
- [ ] Carousel rail uses strong severity background tokens only (`*-strong` variables), not base banner surface tokens.
- [ ] Carousel rail is in-flow (no absolute overlay + fixed leading inset); spacing before `LeadingStatusIcon` matches layout contract.
- [ ] Carousel chevrons meet contrast vs rail + counter text (not mid-gray on dark rails).
- [ ] Icon names map to canonical IDS assets or destination icon component names.
- [ ] No hardcoded visual values replace semantic color tokens (except Figma-documented `22px` rail inner gap where no spacing token exists).

## Implementation reconciliation (Storybook + spec)

Captured here so spec-driven codegen and reviews stay aligned with the current reference UI:

| Topic | Contract |
|---|---|
| Carousel item data | Host-owned list; component receives a single `message` for the active item and `carousel.{currentItem,totalItems}` plus `onPrevious` / `onNext`. |
| Carousel rail fill | `var(--color-background-alerting-critical-strong)`, `var(--color-background-alerting-major-strong)`, `var(--color-background-alerting-minor-strong)`, `var(--color-background-alerting-info-strong)` for the four severities—**semantic vars only**, no hex fallbacks in CSS. |

| Demo / QA | Storybook: `CarouselInteractive`, `CarouselInteractiveInformational` demonstrate add/remove items and prev/next; static `WithCarousel` remains for fixed `1 of 4` layout checks. |
