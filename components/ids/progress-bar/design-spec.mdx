## Anatomy
- Progress container (track)
- Progress fill bar
- Optional percentage label
- Optional status text
- Focus ring for keyboard navigation
- Optional step indicators
## Layout & Measurements
- Standard height: 8px
- Large height: 12px
- Container width: 100% of available space
- Border radius: 4px (standard), 6px (large)
- Focus ring: 2px offset from container
- Minimum width: 200px
- Label spacing: 8px from progress bar
- Step indicator size: 12px × 12px

## States (Dark Theme)
- Uses semantic tokens that automatically adapt to dark theme
- Text and border colors remain consistent via semantic variables
- Progress fill colors maintain visibility in dark theme
- Disabled state uses gray tokens for dark theme compatibility
## Interactions
- Progress bar is typically non-interactive (display only)
- Focus ring appears when progress bar is keyboard focusable
- Hover states not applicable (non-interactive)
- Progress value updates dynamically
- Indeterminate state shows continuous animation
- Step indicators show current progress step
### Accessibility
- Focus ring: 2px brand color border
- Keyboard navigation: Tab to progress bar when focusable
- Screen reader support: Proper ARIA attributes for progress indication
- High contrast: Meets WCAG AA standards with provided colors
- Semantic HTML: Use progress element with proper attributes
- Progress announcements: Screen reader announces current progress
- Focus management: Clear focus indication when focusable

### Behavior & guidelines
- Use progress bars to show completion status
- Provide clear labels when showing percentage
- Use color variants to indicate status
- Consider indeterminate state for unknown progress
- Test with screen readers for proper progress announcement
- Use appropriate animation speeds for indeterminate state
- Ensure progress fills are clearly visible
- Consider responsive behavior for different screen sizes
## Composition & API (runtime)
- `type: "inline" | "with-label" | "indeterminate"` (default `"inline"`)
- `thickness: "thin" | "medium" | "thick"` (default `"medium"`)
- `state: "in-progress" | "completed-success" | "completed-warning" | "failed-error"` (default `"in-progress"`)
- `value?: number` (0-100 for determinate modes)
- `label?: string`
- `helperText?: string`
- `showHelperText?: boolean` (default `false`)
- `ariaLabel?: string`
### Variants
- **Default**: Standard blue progress bar
- **Success**: Green progress for successful completion
- **Warning**: Yellow progress for caution states
- **Error**: Red progress for error states
- **Indeterminate**: Animated progress for unknown duration
- **Disabled**: Non-interactive disabled state
- **With Label**: Progress with percentage text
- **Stepped**: Progress with step indicators
## Codegen Contract (Framework-Agnostic Blueprint)
- Deterministic slot order:
  1. `ProgressRoot`
  2. `ProgressTrack`
  3. `ProgressFill`
  4. `ProgressLabel?`
  5. `ProgressHelperRow?`
Variant matrix:
  - `type`: `inline | with-label | indeterminate`
  - `thickness`: `thin | medium | thick`
  - `state`: `in-progress | completed-success | completed-warning | failed-error`
- Behavior contract:
  - determinate modes clamp value between `0` and `100`
  - indeterminate mode ignores value and renders animated fill
  - status state controls fill/border/icon tokens per state table
- Accessibility contract:
  - use `role="progressbar"` for determinate variants with `aria-valuemin`, `aria-valuemax`, `aria-valuenow`
  - provide readable text label for status/progress context
- Fallback/error rules:
  - unknown `type` -> `inline`
  - unknown `thickness` -> `medium`
  - unknown `state` -> `in-progress`
