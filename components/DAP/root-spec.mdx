## Interaction Baseline

- Visible focus indicators are mandatory; use `--color-border-brand-base`.
- Keyboard support:
  - `Tab` for focus traversal
  - `Enter` / `Space` for activation
  - `Escape` for dismissible overlays/drawers
- Hover/press states must be token-driven.
- Disabled state must block interaction and use disabled token set.

## Accessibility Baseline

- WCAG AA contrast targets (4.5:1 normal text, 3:1 large text/non-text UI where applicable)
- All interactive controls are keyboard operable
- Semantic HTML first; ARIA when semantic primitives are insufficient
- State changes must be perceivable to assistive technologies

## Theming Mechanism

- DAP uses semantic CSS custom properties resolved per theme mode.
- Runtime selectors:
  - Light/default: `html[data-design-system="dap"]`, `body[data-design-system="dap"]`
  - Dark: `html[data-design-system="dap"][data-theme="dark"]`, `body[data-design-system="dap"][data-theme="dark"]`
- Global DAP token stylesheet:
  - `components/dap-theme.css`

- All `components/DAP/<slug>/design-spec.mdx` files inherit this root contract.
- Component specs can override only component-specific anatomy, variants, and interactions.
- Generators must:

  - Avoid hardcoded style constants when a token exists.
