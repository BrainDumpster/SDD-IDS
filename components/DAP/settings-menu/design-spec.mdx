## Layout & Measurements
- Sample panel size from Figma instances: `278px` wide, `984px` high.
- Panel top spacing: `16px`.
- Panel right divider: `1px` (`var(--color-border-light)`).
- Title horizontal padding: `24px`.
- Title typography block height follows Header-5 rhythm (`24/32`).
- Item row padding: `8px 24px`.
- Item row vertical rhythm: Body-1 (`16/24`) with `8px` row gap in list stack.
- Selected row treatment:
  - row fill: `var(--color-background-brand-lighter)`
  - text color: `var(--color-text-brand-strong)`
  - leading active indicator: `4px` inset bar in strong brand tone (maps to `var(--color-border-brand-dark)`/`var(--color-text-brand-strong)` family).
  - selected row right edge overlays panel divider by `1px` so the selected surface owns the right boundary in that row.
- Root width is container-driven at runtime; `278px` is sample width from reference frame.

## Interactions
- Clicking an item sets selected state and active indicator on that row.
- Hover applies brand-lighter background; text remains neutral-strong.
- Press applies brand-light background and brand-strong text.
- Press is a runtime interaction state (`:active` equivalent), not demo-only.
- Keyboard:
  - `Tab` to move focus into list.
  - `ArrowUp` / `ArrowDown` to move between items (roving focus pattern when implemented).
  - `Enter` / `Space` to activate current item.
- Focus states map to the two documented variants only: `default-focus` and `selected-focus`.
- Selected state persists until another item is selected.

## Composition & API (runtime)
Main inputs:
- `title?: string` (default `"Settings"`)
- `items: SettingsMenuItemInput[]` (required; user-defined nav items)
- `selectedId?: string`
- `defaultSelectedId?: string`
- `interactive?: boolean` (default `true`)
- `ariaLabel?: string` (default `"Settings Menu"`)

Child-composition model:
- `SettingsMenuRoot` owns structure and interaction state; consumers provide the repeated `SettingsMenuItem` definitions.
- Each nav item is consumer-defined (`id`, `label`, optional `href`/`routeRef`, optional `disabled`) and rendered in declared order.
- Frameworks that support JSX/templated children may expose `SettingsMenuItem` as explicit child nodes; JSON/config-driven frameworks may pass the same contract through `items[]`. Both are equivalent contracts.

Per-item inputs:
- `id: string` (required stable key)
- `label: string` (required)
- `href?: string`
- `routeRef?: string`

Outputs/events:
- `onSelect?(itemId: string): void`
- `onNavigate?(payload: { itemId: string; href?: string; routeRef?: string }): void`

## Codegen Contract (Framework-Agnostic Blueprint)
Deterministic structure:
- `SettingsMenuRoot`
  - `SettingsMenuPanel`
    - `SettingsMenuTitle`
    - repeated `SettingsMenuItem`
      - `SettingsMenuItemLabel`
      - optional `SettingsMenuItemActiveIndicator` (selected only)

Variant/option matrix:
- Context background: `surface-1 | surface-2`
- Item state: `default | hover | press | selected | default-focus | selected-focus`
- Runtime mode: `interactive | forced-state-demo`

Per-slot style contract:
- Panel always carries right divider and component background.
- Title always uses Header-5 rhythm and 24px horizontal inset.
- Items use Body-1 rhythm with 24px horizontal inset.
- Selected item uses brand-lighter fill, brand-strong text, and 4px leading active indicator.
- Selected item also overlays the panel right divider by `1px` to visually cover that edge in the selected row.

Behavior contract:
- Exactly one selected item in single-select mode.
- If `selectedId` provided, component is controlled.
- If uncontrolled, initialize with `defaultSelectedId` or first enabled item.
- No disabled row state is defined in the canonical DAP state node; generators must not fabricate a disabled visual variant unless a separate DAP source node is provided.

Accessibility contract:
- Root uses `nav` and `aria-label`.
- Each interactive row uses semantic button/link pattern.
- Selected item exposes `aria-current="page"` when used as route navigation.
- Focus-visible indicator must remain visible and unclipped.

Asset/bundling contract:
- No icon asset required for this minimal settings-menu variant.
- If icons are added in future variants, resolve through shared `Icon` primitive and documented slugs.

Fallback/error rules:
- Unknown/missing `selectedId` falls back to first enabled item.
- Duplicate item IDs are validation errors.
- Empty item list renders title-only panel in non-interactive mode.
