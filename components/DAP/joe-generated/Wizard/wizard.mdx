## Layout & Measurements
- Figma sample "one size" frame: `1594px x 843px` (sample only; runtime is token/prop driven).
- Wizard body region is two columns (`steps pane` + `content pane`) with equal vertical span.
- Footer belongs to the **content pane only** (right column) and is anchored at its bottom.
- Steps pane continues full height beside the content pane/footer stack (left column is not shortened by footer).
- Width behavior is container-driven in runtime; size presets are max-width constraints (`medium|large|x-large`) and must not clip right-side footer actions.
- Header padding: `20px 24px` (right side includes close action spacing in sample).
- Header has **no bottom divider line** in the verified sample.
- Footer padding: `24px`; footer has top border.
- Footer uses a 1px top border (`--color-border-accessible`) and no shadow treatment.
- Steps pane sample width: `256px`.
- Step row padding: `8px 34px` with optional right-side status indicator.
- Step rows are borderless in default state; only the pane separator and selected-row leading accent are visible.
- Step active accent: 4px leading stripe style (tokenized brand strong color).
- Content pane has page title block + body content block + optional inner scroll gradients.
- Page content area does not add a bottom border to separate footer.
- `WizardPageContent` container uses a gradient bottom border treatment (not a separate overlay layer) with:
  - start: `var(--color-gradient-overflow-vertical-start)`
  - end: `var(--color-gradient-overflow-vertical-end)`
- Supported runtime sizes:
  - `medium`: `576px`
  - `large`: `864px`
  - `x-large`: `1152px`
  - `full-screen`: viewport-constrained (`100vw/100vh` in modal; container fill in inline)
- Modal mode uses backdrop and centered shell; inline mode renders in normal document flow.

## Interactions
- Clicking step/substep navigates to that page when target is visible and enabled.
- Parent step with children acts as group node and does not own page content; selecting it moves focus to first visible child.
- Steps/substeps can be shown/hidden at runtime through conditional visibility rules.
- Steps/substeps can be injected dynamically at runtime; flow recalculates navigation/progress labels immediately.
- Footer `Next`/`Finish` primary action respects validation state (`enabled`/`disabled`).
- Page-specific footer actions can replace default footer button set.
- Footer progress label format:
  - top-level step page: `Step 1 of 5`
  - substep page: `Step 2a of 5`
- Button events are emitted for `Cancel`, `Previous`, `Next`, and `Finish`.
## Composition & API (runtime)
Main inputs:
- `mode?: "inline" | "modal"` (default `"inline"`)
- `size?: "medium" | "large" | "x-large" | "full-screen"` (default `"large"`)
- `title: string`
- `steps: WizardStepInput[]` (required; supports nested children)
- `initialStepId?: string`
- `showCloseButton?: boolean` (default `true`)
- `isPrimaryEnabled?: boolean | ((ctx: WizardContext) => boolean)` (default `true`)

`WizardStepInput`:
- `id: string`
- `label: string`
- `pageTitle?: string`
- `content?: Renderable` (required for leaf steps; optional for parent steps with children)
- `status?: "none" | "success" | "warning" | "error"`
- `statusIconSlug?: string | null` (optional; when `null`, suppress icon rendering even if `status` is set)
- `isVisible?: boolean | ((ctx: WizardContext) => boolean)` (default `true`)
- `children?: WizardStepInput[]`
- `footerButtons?: WizardFooterButtons` (optional page override)

`WizardFooterButtons`:
- `showCancel?: boolean`
- `showPrevious?: boolean`
- `primaryLabel?: "Next" | "Finish" | string`

Outputs/events:
- `onCancel(event: WizardEventPayload): void`
- `onPrevious(event: WizardEventPayload): void`
- `onNext(event: WizardEventPayload): void`
- `onFinish(event: WizardEventPayload): void`
- `onStepChange(event: WizardEventPayload): void`

`WizardEventPayload` includes:
- `stepId`
- `parentStepId?`
- `stepIndex` (top-level index)
- `substepIndex?` (child index)
- `stepCode` (e.g., `2`, `2a`)
## Codegen Contract (Framework-Agnostic Blueprint)
Deterministic structure:
- Always render `WizardHeader`, `WizardBody`, `WizardFooter`.
- `WizardStepsPane` left, `WizardContentPane` right.
- Parent nodes with children render as grouping rows; leaf nodes map to content pages.

Variant/options matrix:
- mode: `inline | modal`
- size: `medium | large | x-large | full-screen`
- step tree: `flat | nested`
- visibility: `static | conditional`
- footer actions: `default | per-page override`
- primary action state: `enabled | disabled`

Per-slot style contract:
- Step rows must use `Body 1` tokenized text sizing.
- Header block must not introduce a dedicated bottom border.
- Step rows must remain borderless; selected row highlight is the only row-level stroke treatment (4px leading accent).
- Page titles must use `Header 5`; page body content defaults to `Body 2`.
- Status indicators render on right side of step rows.
- Footer progress text uses `Body 2`.

Behavior contract:
- Navigation model is leaf-step based.
- `Next` advances to next visible leaf.
- `Previous` goes to previous visible leaf.
- Parent with children has no page and reports consolidated status from child statuses (`error > warning > success > none` priority).
- Dynamic injection/removal preserves nearest valid current leaf.

Accessibility contract:
- Root uses `role="region"` (inline) or dialog semantics (modal mode).
- Steps list uses `role="tree"` with nested `treeitem` semantics (or equivalent nav semantics by framework).
- Active step communicates `aria-current="step"`.
- Footer buttons are keyboard reachable and emit on Enter/Space.

Asset resolution and bundling:
- Status icon slugs:
  - default success: `shape-check`
  - default warning: `status-warn-tri-solid-16`
  - default error: `status-error-diamond-solid`
  - `statusIconSlug` is optional per step; if omitted, defaults above are used from `status`
  - set `statusIconSlug: null` to render no status icon for that step
- Optional close icon slug: `ctrl-close-16` (fallback to local close glyph if missing).

Fallback/error rules:
- If `initialStepId` is invalid, start at first visible leaf.
- If no visible leaf exists, render empty state and disable primary/previous.
- If parent has children and all hidden, parent is hidden.
- If step content missing for a leaf, render guarded placeholder message.

Validation checklist:
- [ ] Supports flat + nested steps with deterministic ordering.
- [ ] Parent-with-children has no page and computes consolidated status.
- [ ] Conditional visibility and runtime injection update navigation flow safely.
- [ ] Progress labels render `Step N of T` and `Step Na of T`.
- [ ] Footer default and page override buttons both work.
- [ ] Cancel/Previous/Next/Finish emit typed events.
- [ ] Primary action disabled state is respected.
- [ ] Modal and inline mode + all sizes render correctly.
